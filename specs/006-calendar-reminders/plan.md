# Implementation Plan: Calendar Reminders for Bills

**Branch**: `006-calendar-reminders` | **Date**: 2026-05-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/006-calendar-reminders/spec.md`

## Summary

Extend the NoDues bill management system with automatic Google Calendar reminder events. When a bill has a due date and its bill type has `reminderOffsetsDays` configured, the system creates one all-day event per offset on the "NoDues Reminders" calendar. Events are managed as best-effort side effects of bill lifecycle operations (add/edit/mark-paid/delete/undo). The bill Sheet write always succeeds first; calendar operations never block or corrupt it. A passive Bell indicator on BillCard shows when reminders are active.

## Technical Context

**Language/Version**: TypeScript 5.x, React 19, ES2022+

**Primary Dependencies**: React 19, React Router, Tailwind CSS, Lucide React, Google Calendar API v3, Google Sheets API v4

**Storage**: Google Sheets (primary data via Sheets API), Google Calendar (reminder events via Calendar API). No local database.

**Testing**: Manual testing against live Google APIs (no test framework in the project)

**Target Platform**: Mobile-first web app (PWA-capable), primary viewport 375px (iPhone). Runs in any modern browser.

**Project Type**: Single-page web application (React + Vite). No backend server.

**Performance Goals**: Calendar API calls should complete within 2-3 seconds total for a typical bill type with 2-3 offsets. Bill Sheet write must not be delayed by calendar operations.

**Constraints**: Best-effort architecture — calendar failures must never prevent bill persistence. Single-user app — no concurrent-write protection needed. OAuth token already has calendar scope (granted in Phase 2).

**Scale/Scope**: Single household user. Typically 10-30 active bills. 2-3 reminder offsets per bill type. Calendar operations are infrequent (triggered by manual bill CRUD).

## Implementation Design

### Layer 1: calendarService.ts Extensions

Add two functions to the existing `calendarService.ts`:

#### `createAllDayEvent(accessToken, calendarId, dateYYYYMMDD, title, description) → Promise<string>`

- **API**: `POST /calendar/v3/calendars/{calendarId}/events`
- **Request body**:
  ```json
  {
    "summary": "{title}",
    "description": "{description}",
    "start": { "date": "{dateYYYYMMDD}" },
    "end": { "date": "{nextDay(dateYYYYMMDD)}" },
    "reminders": {
      "useDefault": false,
      "overrides": [{ "method": "popup", "minutes": 0 }]
    }
  }
  ```
- **Critical**: `end.date` is the day AFTER `start.date` (exclusive). A single-day all-day event with `start.date = "2026-06-08"` needs `end.date = "2026-06-09"`. Without this, the event may not render.
- **Pattern**: `withRetry(() => googleApiFetch<GoogleCalendarEvent>(...))`, same as `createCalendar`.
- **Returns**: `event.id` (string).
- **nextDay computation**: Compute inline within `createAllDayEvent` — parse YYYY-MM-DD, add 1 day via `new Date(y, m-1, d+1)`, reformat. This keeps calendarService independent of billsService. (The billsService `nextDay` helper also exists for the orchestration layer but calendarService doesn't import it.)

#### `deleteEvent(accessToken, calendarId, eventId) → Promise<void>`

- **API**: `DELETE /calendar/v3/calendars/{calendarId}/events/{eventId}`
- **404/410 handling**: Catch `GoogleApiRequestError` and check `error.status`. If 404 or 410, return silently (event already gone). Otherwise re-throw.
- **Pattern**: `withRetry(() => googleApiFetch(..., { method: 'DELETE' }))`, wrapped in try/catch for 404/410.
- **Returns**: `void` (204 No Content on success, handled by `googleApiFetch`'s `response.status === 204` branch).

### Layer 2: billsService.ts Extensions

#### Event ID Helpers

```typescript
export const parseEventIds = parseFileIds;       // alias
export const serializeEventIds = serializeFileIds; // alias
```

Identical CSV format. Named exports for call-site clarity.

#### Pure Date Helpers

Three pure, testable functions:

1. **`computeReminderDate(dueDateStr, offsetDays) → string`**: Subtract days from a YYYY-MM-DD date. Uses `new Date(year, month-1, day-offsetDays)` for safe rollover. Returns YYYY-MM-DD.

2. **`nextDay(dateStr) → string`**: Add 1 day to a YYYY-MM-DD date. Uses `new Date(year, month-1, day+1)`. Needed for all-day event exclusive `end.date`.

3. **`formatDueDate(dateStr) → string`**: Convert `"2026-06-05"` to `"5 Jun 2026"`. Reuses the same month abbreviation table as `formatMonth`. Day is unpadded.

#### Full-Row-Safety Setter

**`setCalendarEventIds(accessToken, spreadsheetId, bill, eventIds) → Promise<Bill>`**:
- Mirrors `addFileIdToBill` pattern exactly:
  1. Spread `...bill`
  2. Overwrite `calendarEventIds: serializeEventIds(eventIds)`
  3. Bump `updatedAt: new Date().toISOString()`
  4. `updateRow(accessToken, spreadsheetId, TAB_NAME, bill._rowIndex, serializeRow(updatedBill))`
- Pass `[]` to clear all event IDs.
- Returns updated Bill.

#### Calendar Orchestration

**`createReminders(accessToken, calendarId, dueDate, reminderOffsetsDays, billTypeName, propertyName, amount, month) → Promise<ReminderResult>`**:

```typescript
interface ReminderResult {
  eventIds: string[];
  allSucceeded: boolean;
}
```

Implementation:
1. If `reminderOffsetsDays` is empty, return `{ eventIds: [], allSucceeded: true }`.
2. Build the event title: `"{billTypeName} — {propertyName} due {formatDueDate(dueDate)}"` (uses em-dash `\u2014`).
3. Build the description: `"Month: {formatMonth(month)}"` + optional `"\nAmount: {formatCurrency(amount)}"`.
4. For each offset in `reminderOffsetsDays` (sequentially):
   a. Compute `reminderDate = computeReminderDate(dueDate, offset)`.
   b. Call `createAllDayEvent(accessToken, calendarId, reminderDate, title, description)`.
   c. If success: push event ID to `eventIds`.
   d. If error: catch, set `allSucceeded = false`, continue to next offset.
5. Return `{ eventIds, allSucceeded }`.

**`cleanupReminders(accessToken, calendarId, eventIds) → Promise<void>`**:

Implementation:
1. For each event ID (sequentially):
   a. Call `deleteEvent(accessToken, calendarId, eventId)`.
   b. Catch any errors — cleanup is best-effort, never throws.
2. Return void.

### Layer 4: BillsPage Handler Wiring

All bill handlers in BillsPage gain calendar side-effect logic after the primary Sheet write. The pattern is consistent across all handlers.

#### Prerequisite: Access calendarId

```typescript
const calendarId = setupResult!.calendarId;
```

Already available via `useBootstrap()` (confirmed `SetupResult.calendarId` exists).

#### Prerequisite: Modify refetchBills to return data

```typescript
async function refetchBills(): Promise<BillWithDisplay[]> {
  const billData = await fetchBills(accessToken!, spreadsheetId, billTypeMap);
  setBills(billData);
  return billData;
}
```

This allows handlers to find the freshly-added bill by ID (solves React state closure issue where `bills` in the handler closure is stale after `setBills`).

#### Handler: saveNewBill (addBill)

```
1. const newBill = await addBill(...)                    // Sheet write (always first)
2. const freshBills = await refetchBills()               // Get bill with correct _rowIndex
3. if (newBill.dueDate && billType.reminderOffsetsDays.length > 0):
   a. try:
      - result = await createReminders(accessToken, calendarId, ...)
      - if result.eventIds.length > 0:
        - freshBill = freshBills.find(b => b.id === newBill.id)
        - updated = await setCalendarEventIds(freshBill, result.eventIds)
        - setBills(prev => prev.map(b => b.id === updated.id
            ? { ...b, calendarEventIds: updated.calendarEventIds } : b))
      - if !result.allSucceeded:
        - showToast('Bill saved, but some reminders couldn\'t be set.', 'error')
   b. catch:
      - showToast('Bill saved, but reminders couldn\'t be set.', 'error')
4. showToast('Bill added.', 'success')  // only if no calendar error toast shown
```

**Why refetch before calendar ops**: `addBill` returns a bill with `_rowIndex = -1` (row index unknown after `appendRows`). `setCalendarEventIds` needs a valid `_rowIndex` for `updateRow`. The refetch provides the correct index.

#### Handler: saveEditBill (updateBill)

```
1. Compare old dueDate (bill.dueDate) vs new dueDate (data.dueDate)
2. const updatedBill = await updateBill(...)              // Sheet write (always first)
3. if dueDate CHANGED (bill.dueDate !== data.dueDate):
   a. try:
      - oldEventIds = parseEventIds(bill.calendarEventIds)
      - if oldEventIds.length > 0:
        - await cleanupReminders(accessToken, calendarId, oldEventIds)
      - if data.dueDate !== '' (date changed, not removed):
        - result = await createReminders(accessToken, calendarId, data.dueDate, ...)
        - updated = await setCalendarEventIds(updatedBill, result.eventIds)
        - setBills(prev => prev.map(b => b.id === updated.id
            ? { ...b, calendarEventIds: updated.calendarEventIds } : b))
        - if !result.allSucceeded: toast partial warning
      - else (date removed):
        - updated = await setCalendarEventIds(updatedBill, [])
        - setBills(prev => prev.map(b => b.id === updated.id
            ? { ...b, calendarEventIds: updated.calendarEventIds } : b))
   b. catch:
      - showToast('Bill updated, but reminders couldn\'t be updated.', 'error')
4. if dueDate UNCHANGED: no calendar ops
5. await refetchBills()
```

**Why updatedBill has valid _rowIndex**: `updateBill` spreads from `existingBill` which was fetched and has the correct `_rowIndex`. No refetch needed.

#### Handler: handleMarkPaidSubmit (markBillPaid)

```
1. const paidBill = await markBillPaid(...)               // Sheet write (always first)
2. if markPaidTarget.calendarEventIds:
   a. try:
      - await cleanupReminders(accessToken, calendarId,
            parseEventIds(markPaidTarget.calendarEventIds))
      - await setCalendarEventIds(paidBill, [])           // Clear IDs in sheet
   b. catch:
      - showToast('Bill marked paid, but calendar reminders couldn\'t be removed.', 'error')
3. await refetchBills()
```

#### Handler: handleDeleteConfirm (softDeleteBill)

```
1. Optimistic UI remove (existing logic)
2. await softDeleteBill(...)                              // Sheet write (sets deleted_at)
3. if bill.calendarEventIds:
   a. try:
      - await cleanupReminders(accessToken, calendarId,
            parseEventIds(bill.calendarEventIds))
   b. catch:
      - showToast('Bill deleted, but calendar reminders couldn\'t be removed.', 'error')
4. NOTE: Do NOT call setCalendarEventIds here. softDeleteBill uses updateCell
   to set deleted_at. A subsequent setCalendarEventIds (full-row write) with the
   pre-delete bill object (deletedAt='') would overwrite deleted_at, effectively
   un-deleting the bill. Stale event IDs are harmless for a deleted bill.
```

#### Handler: undo callback (undoDeleteBill)

```
1. await undoDeleteBill(...)                              // Sheet write (clears deleted_at)
2. let restoredBill = bill
3. const billType = billTypes.find(bt => bt.id === bill.billTypeId)
4. if bill.dueDate && billType && billType.reminderOffsetsDays.length > 0:
   a. try:
      - result = await createReminders(accessToken, calendarId, ...)
      - if result.eventIds.length > 0:
        - restoredBill = await setCalendarEventIds(bill, result.eventIds)
      - if !result.allSucceeded:
        - showToast('Bill restored, but some reminders couldn\'t be recreated.', 'error')
   b. catch:
      - showToast('Bill restored, but reminders couldn\'t be recreated.', 'error')
5. setBills(prev => {
     const next = [...prev];
     next.splice(originalIndex, 0, {
       ...restoredBill,
       billTypeName, propertyName, propertyId, displayStatus  // re-enrich
     });
     return next;
   })
```

### Cross-Cutting Concerns

#### Toast Messages (FR-029)

| Operation | Calendar Failure Toast |
|-----------|----------------------|
| addBill | "Bill saved, but reminders couldn't be set." |
| updateBill | "Bill updated, but reminders couldn't be updated." |
| markBillPaid | "Bill marked paid, but calendar reminders couldn't be removed." |
| softDeleteBill | "Bill deleted, but calendar reminders couldn't be removed." |
| undoDeleteBill | "Bill restored, but reminders couldn't be recreated." |

All toasts use `'error'` severity. The primary operation's success is implicit in the message prefix ("Bill saved", "Bill marked paid", etc.).

#### Full-Row-Safety (FR-028)

All `setCalendarEventIds` calls follow the established pattern (mirror of `addFileIdToBill`):
1. Spread existing bill (`...bill`)
2. Overwrite target field (`calendarEventIds`)
3. Bump `updatedAt`
4. Write full row via `updateRow`

#### Error Classification (FR-027)

- `createAllDayEvent` and `deleteEvent` use `withRetry` (retries on 429, 500, 502, 503).
- 401 (auth) and 403 (permission) errors are not retried (existing `withRetry` behavior in `googleApi.ts`).
- `deleteEvent` treats 404/410 as success (event already gone).
- `createReminders` catches per-event errors and preserves partial results.
- `cleanupReminders` catches all errors and never throws.
